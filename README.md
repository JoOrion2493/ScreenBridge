# ScreenBridge —— 多屏幕窗口与布局管理工具

声明：本项目思路借鉴了华硕ScreenXpert的一些操作，仅为在华硕台式机和其他品牌上实现类似屏幕窗口管理功能。代码完全由AI编写，任何组织和个人都不得使用本项目进行修改盈利。

## 一、悬浮球

平时就是右下角一枚圆形 logo（`logo.png` 做的，圆外全透明，没有方角白雾）：

![ball](shot-ball-exe.png)

点一下，向上展开竖向图标栏

![bar](shot-ball-exe-menu.png)

| 图标    | 点击后                        |
| ----- | -------------------------- |
| 摄像头   | 打开/关闭摄像头（关掉时图标上划一道红斜杠）     |
| 麦克风   | 静音/取消静音（静音时同样划斜杠）          |
| 布局管理器 | 三分区图标（左大格＋右两小格）。开启：白描边＋左格蓝色高亮；关闭：灰描边＋红斜杠。开关"拖标题栏选布局"这套功能，关掉后拖动不再弹面板 |
| 设置    | 展开下面的设置面板                  |

设置面板四个开关、一行大小选择，再加退出：

![settings](shot-panel-over-white.png)

| 项      | 说明                                         |
| ------ | ------------------------------------------ |
| 始终置顶   | 关掉后悬浮球只是普通浮动窗口，会被别的窗口盖住                    |
| 开机自动启动 | 写 `HKCU\...\Run`，不需要管理员                    |
| 贴靠屏幕边缘 | 打开后，**把球拖到屏幕边缘**松手才收成一条半透明蓝色短条；拖到别处松手就留在原地 |
| 隐藏悬浮球  | 一个真正的开关：打开收起球，再点一下又出来；球收起时托盘双击/右键菜单也能叫回来   |
| 面板大小   | 布局管理面板的**大 / 中 / 小**三档，选中的那一格会亮起来；切换立刻生效 |

**为避免影响用户使用，退出会把摄像头和麦克风恢复成开启状态**

### 贴边收起

**只有把球拖到屏幕边缘上松手**才会贴靠（离边缘 16 DIP 以内算"拖到了边上"）。拖到屏幕中间松手，球就老老实实停在鼠标松开的位置，不会被吸到边上：

![docked](shot-ball-live-docked.png)

点这条蓝色短条，球会**恢复成一枚正常的悬浮球**（同时展开图标栏）

![docked menu](shot-ball-live-docked-menu.png)

竖边是竖条，横边（上/下边缘）自动变成横条。想彻底不贴边，把设置里的"贴靠屏幕边缘"关掉即可

### 托盘图标

右键是**传统的 Win32 菜单**

![tray](shot-tray-menu.png)

| 菜单项       | 作用                  |
| --------- | ------------------- |
| 显示悬浮球     | 打勾表示球在屏幕上；点击收起/叫回   |
| 拖动标题栏选择布局 | 打勾表示布局管理器在用；点击暂停/恢复 |
| 设置…       | 打开设置面板（球隐藏时也能用）     |
| 退出        | 恢复摄像头和麦克风后退出        |

托盘图标**双击**是"显示/隐藏悬浮球"的快捷方式。

## 二、拖标题栏选布局

拖动标题栏后，面板出现在**鼠标下方**。第一阶段只有一排屏幕图标，每个是一块显示器（宽高比按真实屏幕画）：

![stage 0](shot-palette-stage1.png)

鼠标在某个屏幕图标上停一下（默认 90ms），它下面展开5套预设布局。每套都按**常用的分屏布局**进行绘制，鼠标停在哪一格，那一格就变白——白色那格就是窗口会落到的位置：

![stage 1](shot-palette-stage2.png)

**展开时面板一格都不许动**：屏幕图标行被钉在光标下方，只有布局行在它对面展开。光标靠近屏幕底部、下方放不下时，布局行翻到图标行上方（图标行仍然不动）：

![flip](shot-palette-flip.png)


## 三、落位：同屏直接摆，跨屏才做动画

| 场景            | 行为                                            | 时长    |
| ------------- | --------------------------------------------- | ----- |
| 同一块屏上换布局 / 归位 | **直接摆过去**，不做动画                                | 0     |
| 窗口搬到另一块屏      | **先缩小 → 穿越 → 展开**：缩到约 30%、小尺寸横穿两块屏的边框、再在目标格展开 | 560ms |

同屏的缩放动画做过一版，实际用下来"拖完手一松还在动"更像卡顿，所以去掉了：用户刚指过位置，屏幕就该立刻是那个样子。跨屏不一样——窗口如果瞬移，人会以为它丢了，所以保留"缩小—穿越—展开"。

![travel](shot-anim-travel.png)

上面这张是从真实动画里**等间隔采样出来的轨迹**（每一个 ghost 就是那一帧的窗口矩形，不是手画的）。

动画不拿精度换观感：全程只对**可见矩形**插值，每帧按启动时量到的隐形边框换算成窗口矩形，最后一帧再走一遍 `place_visible` 复测校正——落点偏差实测仍是 0px。

| 拖动悬浮球              | 换位置；**只有拖到屏幕边缘松手**才收成蓝色短条，拖到别处就停在那儿 |

## 五、摄像头和麦克风是怎么关的

两件事的做法完全不同，因为 Windows 给的接口完全不同。

**麦克风** —— `IAudioEndpointVolume::SetMute`（对默认采集端点）。这就是音量设置里那个静音按钮做的事：对所有应用生效、立刻生效、**不需要管理员权限**。

**摄像头** —— Windows 从来没提供过"关掉摄像头"的公开 API。「设置 → 隐私 → 相机」那个开关只是往 ConsentStore 写条记录做应用级拦截，设备其实还活着，已经拿到流的程序照旧能用。真正等同"摄像头被关掉"的是让**设备节点进入 Disabled 状态**，也就是设备管理器里右键禁用，对应 `CM_Disable_DevNode`。禁用之后任何程序（浏览器 / 会议 / OBS）都拿不到画面。**代价是要管理员权限**，所以：

- 常驻进程**永远不提权**
- 点摄像头按钮时，用 `ShellExecuteW("runas")` 把自己的 `--camera-set on|off` 拉起来跑一次，只做这一件事
- UAC 被拒不是错误，只是"没改"，界面会说"已取消管理员授权"

退出时的恢复：

1. 先把所有界面隐藏掉
2. 后台线程恢复麦克风（`SetMute(False)`，无需权限）
3. 如果摄像头是我们关的，再提权开回来（会弹一次 UAC）
4. 都做完了才真正退出

## 六、五套布局

| # | id        | 名称   | 格数 |
| - | --------- | ---- | -- |
| 1 | `split-v` | 左右二分 | 2  |
| 2 | `split-h` | 上下二分 | 2  |
| 3 | `third-v` | 三列   | 3  |
| 4 | `quad`    | 四宫格  | 4  |
| 5 | `full`    | 全屏   | 1  |

格一律按**工作区**（`rcWork`）算，不会盖住任务栏。默认间隙 8px、边缘留白 0，配置里可改。

> 早期版本还有 `left-1-2`（左一右二）、`left-2-1`（左二右一）、`top-1-2`（上一下二）三套，
> 它们都只是上面几套的**排布组合**（三分区换个方向、或者一块大一块小），
> 而这套工具的分区是按**格数**算的——再加一种排布只是多一个按钮、少一次误点，
> 并不能表达新的分割语义，所以精简掉了。

## 六之二、屏幕编号与排列

拖动窗口弹出的面板，上方那一排方块是**桌面缩略图**：每块屏幕画在它真实的位置上，
块里写着 **Windows 自己的屏幕编号**（设置 → 系统 → 显示 里的那个编号），
块左上角还有一行字直接写出排列方式。

![palette](shot-live-palette-medium.png)

| 情况         | 面板上的表现                                       |
| ---------- | -------------------------------------------- |
| 一块屏幕       | 一个方块，编号 `1`，左上角写「单屏」                        |
| 主屏 + 副屏（横排） | 两个方块并排，编号按系统来（可能是 `2` 在左、`1` 在右），左上角写「横排 · 2 屏」 |
| 主屏 + 副屏（竖排） | 两个方块上下叠，左上角写「竖排 · 2 屏」                       |
| 三块及以上、任意错位   | 每块屏幕各占一格，保持真实相对位置，左上角写「错落 · N 屏」             |

编号取自 `QueryDisplayConfig` 的**活动路径序号**，和 Windows 设置里看到的完全一致。
不能用 GDI 的 `\\.\DISPLAYn` 名字来代替——那个编号是按适配器分配的，
双显卡机器上笔记本屏是 `DISPLAY1`、外接屏却可能是 `DISPLAY3`，
和设置里显示的 `1`、`2` 对不上。

排列方式判定用的是**虚拟桌面矩形**（`GetSystemMetrics(SM_XVIRTUALSCREEN)`），
不是 `QueryDisplayConfig` 里的 source mode position：
笔记本屏挂在核显、外接屏挂在独显时，两块屏各自的 source mode 都报 (0, 0)，
那个位置说明不了任何排列。

### 选中的屏幕长什么样

被选中的那块屏幕用**强调色描边**（加粗）+ 一层淡蓝底 + 纯白加粗的编号；
没选中的屏幕描边压到半透明、编号也调暗。两者的对比一眼就能看出来：

| 状态   | 边框                | 底色        | 编号         |
| ---- | ----------------- | --------- | ---------- |
| 选中   | 强调蓝，2.6px 加粗     | 淡蓝 52/255 | 纯白加粗        |
| 悬停未选中 | 浅灰，1.8px          | 深灰底       | 灰白         |
| 未选中  | 暗灰，1.4px，140/255   | 透明        | 灰 158/255   |

### 布局面板往哪边开

两块面板（屏幕行、布局行）之间的相对位置**由屏幕怎么排决定**，
目的只有一个：**从屏幕芯片走到布局格，中间不要横穿别的屏幕格子**。

| 屏幕排列        | 布局面板的位置              | 理由                                       |
| ------------ | ---------------------- | ---------------------------------------- |
| 横排（一行）      | 屏幕面板的**下方**（放不下就上方）     | 横向的一行，下方是空的                       |
| 竖排（一列）      | 屏幕面板的**右侧**（放不下就左侧）     | 竖着的一列，右侧是空的；放下方就得从上面那块屏“穿过去” |
| 错位 / 网格 / 多屏 | 按同样的规则逐个方向试，选第一个不挡路的 | 每个方向都会检查“有没有芯片挡在指针和面板之间”        |

方位判定是**逐个方向试**出来的，不是简单查表：

1. 先按排列给出候选顺序（横排 → 下/上/右/左，竖排 → 右/左/下/上，错位 → 下/右/上/左）；
2. 每个方向都检查两件事：**指针和面板之间有没有别的屏幕芯片挡路**、**屏幕边缘还有没有空间**；
3. 两个条件都过的第一个方向胜出。

所以 L 形、三屏、四屏这些组合也能给出不挡路的位置。

![arrangement](shot-palette-arrangement.png)

> 上图：横排 → 布局行在下方；竖排 → 布局行在右侧。

## 六之三、面板大小：大 / 中 / 小

布局管理面板默认是**大**（就是原先的样子）。设置面板里多了一行「面板大小」，
可以切成**中**或**小**，拖窗时弹出的面板会跟着变：

| 档位   | 缩放系数 | 面板尺寸（含阴影）       |
| ---- | ---- | ------------------ |
| 大    | 1.00 | 915 × 375          |
| 中    | 0.78 | 712 × 292          |
| 小    | 0.62 | 569 × 230          |

缩放是叠在显示器 DPI 之上的（`DPI/96 × 尺寸系数`），
所以在 150% 缩放的屏上选「小」，出来的仍然是物理上真正更小的面板。
设置写在 `palette_size` 里，切完立刻生效，不用重启。

![sizes](shot-palette-sizes.png)

### 几个不显眼但会翻车的地方

**1. 最大化过的窗口有"记忆"**——只调 `SetWindowPos` 会被系统拽回旧的还原矩形。必须先 `SetWindowPlacement` 把 `rcNormalPosition` 改掉，再 `SetWindowPos` 精调。原版 `MoveWindowByRect` 也是这两步。

**2. `SetWindowPos` 说的是"窗口矩形"，不是"看得见的那块"**——Win11 的窗口矩形比可见外框每边大 9px（DPI 缩放下的隐形边框）。直接把窗口矩形铺到格上，可见边框会往里缩 9px，相邻两格的视觉间隙从 8px 变成 26px。所以落位是"先摆、再量 `DWMWA_EXTENDED_FRAME_BOUNDS`、再修正"，最多三轮（`engine.place_visible`）。

**3. 展开布局时"面板整体下移/横跳"**（已修）——原来 `_anchor()` 在每次阶段切换时都用**当前**尺寸重算一次锚点，于是布局行比图标行宽 3.5 倍，一按新宽度做边界钳制整块面板就被推到隔壁屏（实测横跳 1044px）；竖直方向下方放不下就翻到上方（实测跳 429px）。现在锚点只算一次，而且屏幕图标行和布局行**各自独立定位**、窗口取两者并集。

**4. 隐藏的窗口还留着上一次的矩形**——判断"这次点击是不是点在面板上"只看几何，就会把一块**已经隐藏**的设置面板也算进去；它停在屏幕左上角，于是点在任意位置都被当成"点在里面"，菜单再也收不起来。判断前必须先问窗口是不是真的显示着（`Layered.shown`）。

**4b. 深色面板别用 250/255 的不透明度**——剩下那 2% 会让底下白底窗口里的字在黑面板上留一层幽灵，比"完全不透明"难看得多。设置面板现在是 255，图标栏 252。

**5. 悬浮球的阴影要在窗口里留够地方**——窗口必须比球大一圈（这里是 16 DIP）。阴影画到窗口边界就被硬裁成四条直边，看起来就是"圆的球外面套了个方的影子"；而阴影层数太少会看出同心圆带，所以用 14 层、每层只加一点 alpha。

## 七、已知边界

- **关摄像头必须要一次 UAC**：设备节点禁用是管理员操作，没有别的路。麦克风不需要。
- **UAC 提权窗口动不了**：普通权限进程无法操作管理员窗口，任何同类工具都一样
- **和 Win11 自带 Snap 并存**：我们只在"拖标题栏"时出现，不占屏幕边缘热区，所以拖到边缘时两套会同时出现；不想要就把 Win11 的吸附关掉
- **全屏独占游戏**、**最小化到托盘的窗口**：没有可拖的顶层窗口，不适用
- **多实例应用**（开了好几个资源管理器）：按光标命中的那个走
- **本沙箱的输入注入限制**：这个环境里 `mouse_event` 能改按键状态、能移动光标，但合成点击投递不到窗口。所以测试里点击是直接给窗口发 `WM_LBUTTONUP`，拖动是"按住按键 + 自己移动光标"让常驻轮询去跟——走的都是真实代码路径。真实鼠标不受影响
